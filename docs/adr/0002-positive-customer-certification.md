# 客户级替代限制用正向认证，而不是新增负向禁用表

参考方案设计了一张负向表 `mat_substitute_customer_forbid`（默认所有替代料对所有客户可用，仅例外被拦截）。
但本项目早已存在 `item_customer_certification(item_id, customer_id, certified_at, expire_at)`：
表已建、已有 seed、物料页已有维护入口，却**从未参与任何校验**。

因此决定：不再新增禁用表，直接把该表接上校验，采用**正向**语义——销售出库场景下，
某替代料要顶替主料给某客户，必须存在该客户对该替代料的**未过期**认证记录（default-deny）。
校验只作用于「替代」这一动作；客户直接下单购买该物料时认证与否不影响正常出库。

正向语义对合规更稳（未认证默认不可用），也少一张表与一套页面。代价是上线后需要先为
「客户 × 替代料」补齐认证记录，否则替代出库会被全部跳过——实施与文档都必须明确这一点。

## Considered Options

- **负向禁用表**（照搬附件）：默认全可用、维护量小，但语义弱于认证，且需新增表与页面。
- **两者并存**：表达力最强，但要定义认证与禁用的优先级冲突规则，复杂度不划算。
