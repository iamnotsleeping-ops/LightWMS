# P3 · 采购管理 实施计划

## Context

P2 已交付库存核心引擎（`postMovement` / `changeStockStatus` / 六项口径），引擎的写函数各自包 `db.transaction()`，`better-sqlite3` 对嵌套事务自动用 SAVEPOINT，因此 P3 可以把「写流水 → 累加已执行量 → 推进单据状态」组合进同一个外层事务，满足规格第四节「四步同事务」的硬性要求。

P3 是**第一个真正的单据模块**，要打通规格第八节验收第 2 条的完整链路：新建采购单 100 件 → 确认 → 部分入库 60 → 在途 = 40 → 剩余入库 40 → 在途 = 0 → 库存 = 100。P4 销售会照搬本阶段确立的单据模式（表头表体、状态机、行级过账、单号序列）。

`purchase_order` / `purchase_order_item` 在 P0 的 `0001_init.sql` 已建好；**采购退货没有对应表**，需新增 `0003_purchase_return.sql`。

已与用户确认的三项范围决策：
1. 前端做**四个页面**：采购单列表、新建/编辑采购单、采购单详情、采购入库。
2. 采购入库采用**行级直接入库**：不新增收货单表，在采购单行上执行本次入库数量，同一事务内写流水 → 累加 `received_qty` → 推进单据状态。
3. **采购退货纳入 P3**：新增 `purchase_return` 表头 + 表体，按已入库数量退货并即时过账。

## 核心算法与业务规则

### 1. 采购单状态机（只能由业务动作推进）

```
draft ──确认──→ confirmed ──(部分入库)──→ partial ──(全部入库)──→ received
  │                 │
  └──取消───────────┴──→ cancelled
```

- **不提供「直接改状态」的接口**，只有 `confirm` / `cancel` / `inbound` 三个动作能推进状态。
- `draft`：表头表体可改、可删除、可确认、可取消。
- `confirmed` / `partial`：表头表体**不可改**，可继续入库，可取消。
- `received` / `cancelled`：终态，不可入库、不可取消。
- **取消已确认单据后，其数量必须从在途统计中消失**（验收 6）——由「在途只统计 `confirmed`/`partial`」自动成立，无需额外清理。

### 2. 在途是派生量，不落字段

```
采购在途(行) = quantity − received_qty − cancelled_qty
采购在途(整) = Σ 行在途, 仅当 purchase_order.status ∈ ('confirmed','partial')
```

`received_qty` 是唯一需要落库的累加量（入库动作推进），`cancelled_qty` P3 保持 0（不做行级取消，行级取消留待后续）。

### 3. 入库动作（行级直接入库）

一次入库请求携带一单的多行数量，整个请求在**一个事务**内完成：

1. 校验单据状态 ∈ (`confirmed`, `partial`)，否则 409
2. 逐行校验 `本次数量 ≤ quantity − received_qty − cancelled_qty`，否则 409
3. 逐行调用 `postMovement({ bizType: 'purchase_in', bizId: 采购单 id, bizNo: 单号, direction: 1, unitCost: unit_price, stockStatus })`
   - **`stockStatus` 由物料决定**：`item.inspection_required = 1` → `qc`（到货即质检中），否则 `available`（规格 §四.5）
4. 逐行 `UPDATE purchase_order_item SET received_qty = received_qty + ?`
5. 重新计算整单状态：全部行 `received_qty + cancelled_qty ≥ quantity` → `received`；否则任一行 `received_qty > 0` → `partial`
6. 更新表头 `updated_at`

入库数量允许小于在途量（分批发货）；每行独立，一次可只入一部分行。

### 4. 采购退货

退货以「已入库的采购单行」为源，**创建即过账**（无草稿态），整个请求一个事务：

1. 校验单据状态 ∈ (`confirmed`, `partial`, `received`)（草稿单没有可退的货）
2. 逐行校验 `退货量 ≤ received_qty − 已退货量`，其中**已退货量不落字段**，实时从 `purchase_return_item` 按 `order_item_id` 求和 —— 与「在途不落字段」同一原则
3. 逐行校验源仓库该物料的 `available` 数量 ≥ 退货量，否则 409（质检中未放行的货不可退，提示先做质检放行）
4. 逐行调用 `postMovement({ bizType: 'purchase_return', direction: -1, ... })`，**按当前移动加权均价结转成本**（引擎出库分支自动实现，不传 `unitCost`）
5. 写 `purchase_return` 表头 + `purchase_return_item` 表体，单号 `PR-YYYYMMDD-NNNN`
6. **退货不改变采购单状态**：已 `received` 的单退货后仍是 `received`（在途已为 0，本就不受影响）

采购退货不涉及财务总账 / 发票 / 退款金额核算（规格第二节明确不做）。

### 5. 单号序列

新增 `packages/server/src/lib/doc-no.ts`：

```ts
nextDocNo(db, docType: DocType, bizDate: string): string
// INSERT INTO doc_sequence(doc_type, biz_date, next_no) VALUES (?, ?, 1)
//   ON CONFLICT(doc_type, biz_date) DO UPDATE SET next_no = next_no + 1
// → 读回 next_no → `${前缀}-${YYYYMMDD}-${补零 4 位}`
```

按「单据类型 + 日期」原子自增，**不用时间戳或随机数**（规格 §四.12）。`DOC_TYPE_PREFIX` 补 `purchase_return: 'PR'`。

### 6. 金额与数量

- `amount = quantity × unit_price`（分），`total_amount = Σ amount`，整数运算，展示层才做除法
- 数量为最小单位整数；`qty_precision > 0` 的物料仅影响前端展示
- 所有写操作包在 `db.transaction()` 内

## 单元测试（规格第八节硬性要求）

`packages/server/src/modules/purchase/purchase.test.ts`，用 `createTestDb()` + `seedFixtures(db)`（已有 RM-001 / FG-001 / WH-01 / SU-01）：

1. **单号序列**：同日两张单为 `PO-YYYYMMDD-0001` / `0002`，跨日重新从 `0001` 起
2. **新建草稿**：`status = draft`，`total_amount = Σ(quantity × unit_price)`
3. **状态机边界**：`draft` 直接入库 → 409；`confirmed` 改表体 → 409；`received` 再次入库 → 409
4. **验收 2 完整链路**：100 件 → 确认 → 入库 60 ⇒ 在途 40 且 `status = partial` → 入库 40 ⇒ 在途 0、`status = received`、库存 100、`avg_cost = unit_price`（分批入库不改变均价）
5. **验收 6 取消单据**：`confirmed` 单取消后，在途统计中其数量消失
6. **超量入库**：`本次数量 > quantity − received_qty` → 409，且 `received_qty` 与库存均无变化
7. **质检隔离**（验收 15 前半）：`inspection_required = 1` 的物料入库 ⇒ 库存进 `qc`，`on_hand` 不变、`frozen`（含 qc）+qty
8. **事务完整性**（验收 5）：一次入库传两行，第 2 行超量抛错 ⇒ 第 1 行的流水、余额、`received_qty` 全部回滚
9. **采购退货**：入库 100 后退 30 ⇒ 库存 70、流水 `biz_type = purchase_return` 且 `direction = -1`、`unit_cost` = 当前均价；退货量为 0 或超可退量 → 409
10. **退货不改单据状态**：`received` 单退货后仍为 `received`
11. **流水与余额恒等**：`SUM(quantity × direction)` ≡ `stock_balance.quantity`（入库 + 退货后仍成立，验收 3）
