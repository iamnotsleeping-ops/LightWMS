## 三、代码与架构审核

### 3.1 后端（packages/server）

模块划分清晰，均为「路由 + 服务（或等价实现）+ 测试」结构，共 9 个模块：

| 模块 | 组成 |
| --- | --- |
| `auth` | routes / auth.service / dingtalk.client |
| `system` | routes / service（用户、角色权限） |
| `masterdata` | index + item/category/warehouse/partner/bom 路由 + bom.service |
| `inventory` | routes / stock.engine / stock.query / transfer.service / stocktake.service / alert.service |
| `purchase` | routes / purchase.service / purchase.inbound |
| `sales` | routes / sales.service / sales.outbound |
| `report` | routes / report.service |
| `dashboard` | routes / dashboard.service |
| `public-api` | routes / public.service / openapi |

- **统一响应信封**：[response.ts](file:///Users/dayu/Library/Application%20Support/TRAE%20SOLO%20CN/ModularData/ai-agent/work-mode-projects/6ac64783f16c026553a13bf8/packages/server/src/lib/response.ts) 提供 `ok()` / `okPage()`，内部与对外接口一致返回 `{code,message,data,page?,_warnings}`；CSV 走 `sendCsv()` 不套信封、带 UTF-8 BOM、告警经 `X-Warnings` 头。
- **权限绑定**：内部路由统一经 `app.requirePermission(code)` 校验，权限码按 `模块.资源.动作` 命名（如 `masterdata.bom.view`、`report.view`）。
- **账本一致性**：`stock_transaction`（不可变流水）+ `stock_balance`（汇总快照），验收断言「每个「物料×仓库×状态」余额 = 该维度流水 direction×quantity 之和」，实际不一致行数为 0。

### 7.1 本轮已处理优化（2026-10-08）

**（1）权限码常量化（对应第 4 项）**

- `packages/shared/src/constants.ts` 新增 `PERMISSIONS`（36 个权限码，与 `0002_rbac_seed.sql` 内置权限一一对应）、`PermissionCode` 类型与 `PERMISSION_CODES` 数组。
- 前端 `layouts/menu.ts` 的菜单权限、后端 10 个路由文件的 `requirePermission` 共 38 处字符串全部替换为常量引用，已确认无残留字符串字面量。
- 视图层 17 个 `.vue` 文件、21 处 `auth.has('<字面量>')`（含 `canManage` / `canConfirm` 计算属性）同样替换为常量。

**（2）前端路由权限守卫（对应第 1 项）**

- `router/index.ts` 的 `beforeEach` 在登录校验后增加权限校验：权限码优先取路由 `meta.permission`，缺省回退到菜单定义（`MENUS`）派生的「查看」权限，使「菜单可见性」与「路由可访问性」同源；按最长 path 前缀匹配。
- 写操作路由（`inventory/transfers|stocktakes` 的 new / edit、`purchase/orders` 的 new / edit、`purchase/inbound`、`sales/orders` 的 new / edit、`sales/outbound`）显式标注 `meta.permission` 为对应 `*.manage` 权限，杜绝「有查看权限即可直达写页面」。
- 无权限访问时 `ElMessage.warning` 提示并重定向到 `/dashboard`。

**（3）按钮级权限指令（对应第 2 项）**
