### 已确定的范围决策

1. **零迁移**：不新增表 / 列 / 索引，不改任何 migration。
2. **公开前缀 `/api/v1`，全部只读 GET，不挂鉴权**（README 已声明）。未挂 `preHandler` 即公开；不改认证插件。
3. **`as_of` 一律从 `stock_transaction` 重算**（沿用 README 全局规则），但**在途 / 预占等单据派生量在历史时点不可还原**：凡历史时点无法还原的字段返回 `null`，并写入 `_warnings`（不静默近似）。具体：
   - IF-3 库存 `as_of`：实物量（`on_hand` / `frozen` / `qc` / `total_qty`）从流水重算；`reserved` / `in_transit` / `available` / `projected` 返回 `null` + 告警（与内部 `queryStockList` 行为一致）。
   - IF-4 在途 `as_of`：**按 `order_date <= as_of` 过滤采购单**，在途量按当前行进度（`quantity − received_qty − cancelled_qty`）计算，并发出「历史单据状态不可还原，按当前进度近似」告警。
4. **参数命名统一 snake_case**（以 README 的 `as_of` 为准）：`as_of` / `page_size` / `item_code` / `warehouse_code` / `supplier_code` / `customer_code` / `category_code` / `parent_item_code` / `child_item_code` / `date_from` / `date_to`。不引入 camelCase 别名（保持文档与 OpenAPI 单一口径）。
5. **分页**：公开接口 `page` 默认 1、`page_size` 默认 100、**上限 1000**（面向机器消费，放宽内部 200 上限）；信封 `page` 对象仍为 `{ page, pageSize, total }`（复用 `okPage`，字段名保持 `pageSize`，与 README 信封一致）。**不分页**的接口：IF-2 BOM 列表（配方主数据，量小，复用 `listBoms` 返回全量数组）、IF-2b 展开（单对象）、IF-5b 提前期聚合（单对象）、IF-7 仓库（主数据，量小）。
6. **`format=json|csv`**：缺省 `json`。
   - `json`：统一信封 `{ code, message, data, page?, _warnings }`，`data` 为数组或对象。
   - `csv`：`Content-Type: text/csv; charset=utf-8`，**带 UTF-8 BOM**（Excel 中文兼容），`Content-Disposition: attachment; filename="<if>-<timestamp>.csv"`；首行列名取该行对象的键序（SELECT 顺序即业务列序，无需额外维护列清单）；`null` → 空串，布尔 → `true/false`，其余原值；**不套信封**（无法承载 `_warnings`，告警改由响应头 `X-Warnings` 传一层摘要，仅在存在告警时输出）。
   - **CSV 仅适用于「扁平行数组」数据集**（IF-1/2/3/4/5/6/7）；IF-2b 展开的 CSV 取 `lines` 扁平序列；IF-5b 聚合的 CSV 输出单行。
   - CSV 与 JSON 享用同一分页参数（同一数据集），不做「导出即全量」的特殊分支。
7. **提前期口径（IF-5 / IF-5b）**：实际到货时刻只能还原到**整单口径**（流水无 `line_no`）。
   - `purchase-history`（IF-5）输出**扁平行级**记录，但 `first_received_at` / `last_received_at` / `lead_time_days` / `promised_lead_time_days` / `on_time` 均为**整单口径**（同一采购单各行共享），字段旁在 README/OpenAPI 中明确标注。
   - `lead_time_days = 日期(last_received_at) − order_date`（天）；`promised_lead_time_days = MAX(promised_date) − order_date`；`on_time = last_received_at <= MAX(promised_date)`。
   - 仅纳入**确有入库流水**的采购单（`stock_transaction.biz_type='purchase_in'`）。
8. **OpenAPI 采用手写静态 3.1 文档**（不引入 `@fastify/swagger` 依赖）：单一来源为 TS 模块 `openapi.ts` 导出的 spec 对象，经 `GET /api/v1/openapi.json` 公开输出（`application/json`）。与仓库「零重依赖、显式优于魔法」的既有风格一致。
9. **前端**：把「系统设置 → 数据接口」菜单点亮为**只读接口文档页** `ApiDocsView.vue`（接口清单 + 参数说明 + curl 示例 + OpenAPI 链接），无权限码（面向已登录用户）、不做在线调试。
10. **`/api/v1` 与内部 `/api` 并存**，互不影响；不改内部路由与既有测试。

## 接口清单与字段口径

统一：`GET`，前缀 `/api/v1`，公开无鉴权，`format` 可选，公开查询参数 snake_case。

### IF-1 `GET /api/v1/items` — 物料主数据
- 参数：`keyword?`、`category_code?`、`is_active?`(0/1)、`page?`、`page_size?`、`format?`
- 数据：`[{ id, code, name, base_unit, qty_precision, category_code, category_name, capacity_group, is_active, inspection_required, batch_managed, serial_managed, created_at, updated_at }]` + `page`

### IF-2 `GET /api/v1/boms?as_of=` — BOM（多版本）
- 参数：`as_of?`、`parent_item_code?`、`child_item_code?`、`keyword?`、`format?`
- 数据（**不分页**）：`[{ id, parent_item_code, parent_item_name, parent_base_unit, child_item_code, child_item_name, child_base_unit, qty_per, scrap_rate, effective_from, effective_to }]`
- 传 `as_of` → 只返回该日期生效版（复用 `listBoms` 的 `asOf`）；不传 → 全部版本

### IF-2b `GET /api/v1/boms/{itemCode}/explode` — 多层展开
- 参数：`as_of?`、`qty?`(默认 1)、`format?`
- 数据：`{ as_of, root: { item_code, item_name, base_unit, qty_precision, required_qty }, lines: [{ level, item_code, item_name, base_unit, qty_precision, qty_per, scrap_rate, required_qty, is_leaf, cyclic }], cycles: string[][] }` + `_warnings`
- 物料不存在 → 404；含循环检测与深度熔断，告警进 `_warnings`

### IF-3 `GET /api/v1/inventory?as_of=` — 库存（含历史快照）
- 参数：`as_of?`、`keyword?`、`item_code?`、`warehouse_code?`、`page?`、`page_size?`、`format?`
- 数据：`[{ item_code, item_name, base_unit, qty_precision, warehouse_code, warehouse_name, warehouse_type, on_hand, frozen, qc, total_qty, reserved, in_transit, available, projected }]` + `page`
- 复用 `queryStockList`：`item_code`/`warehouse_code` 解析为 id 后传入；港口仓过滤沿用 `readPortStockAsInventory`
- `as_of` 时：`on_hand`/`frozen`/`qc`/`total_qty` 由流水重算，`reserved`/`in_transit`/`available`/`projected` = `null` + `_warnings`

### IF-4 `GET /api/v1/in-transit?as_of=` — 在途 / 采购订单
- 参数：`as_of?`、`supplier_code?`、`item_code?`、`status?`（逗号分隔多值，默认 `confirmed,partial`）、`page?`、`page_size?`、`format?`
- 数据：`[{ order_no, order_date, status, supplier_code, supplier_name, line_no, item_code, item_name, base_unit, warehouse_code, warehouse_name, quantity, received_qty, cancelled_qty, in_transit, promised_date }]` + `page`
- `in_transit = quantity − received_qty − cancelled_qty`（仅 `confirmed`/`partial` 状态本轮返回）；`as_of` 按 `order_date <= as_of` 过滤 + 告警（见决策 3）

### IF-5 `GET /api/v1/purchase-history` — 历史采购订单（提前期）
- 参数：`supplier_code?`、`item_code?`、`date_from?`、`date_to?`、`page?`、`page_size?`、`format?`
- 数据（行级，提前期为整单口径）：`[{ order_no, order_date, status, supplier_code, supplier_name, line_no, item_code, item_name, quantity, received_qty, unit_price, promised_date, first_received_at, last_received_at, lead_time_days, promised_lead_time_days, on_time }]` + `page`
- 仅纳入有 `purchase_in` 流水的采购单；`date_from`/`date_to` 作用于 `order_date`

### IF-5b `GET /api/v1/suppliers/{code}/lead-time-stats` — 供应商提前期聚合
- 参数：`item_code?`、`date_from?`、`date_to?`、`format?`
- 数据（单对象）：`{ supplier_code, supplier_name, order_count, line_count, received_line_count, avg_lead_time_days, min_lead_time_days, max_lead_time_days, avg_promised_lead_time_days, on_time_rate, last_order_date }`
- 供应商不存在 → 404；`item_code` 过滤后仅统计含该物料的采购单

### IF-6 `GET /api/v1/sales-orders` — 销售订单行
- 参数：`keyword?`（模糊匹配订单号/客户编码/物料编码/物料名称）、`order_no?`、`customer_code?`、`customer_name?`、`item_code?`、`warehouse_code?`、`status?`（逗号分隔多值，枚举 `draft|confirmed|partial|shipped|cancelled`）、`order_date?`（订单日期精确匹配单日）、`date_from?`/`date_to?`（按「要求交期」`due_date` 区间过滤，双端含边界）、`page?`、`page_size?`、`format?`
- 数据（行级，一行 = 销售单的一行物料）：`[{ order_no, line_no, order_date, customer_code, item_code, warehouse_code, quantity, shipped_qty, unshipped, due_date, status }]` + `page`
- `unshipped = quantity − shipped_qty − cancelled_qty`；`order_date` 为单据维度（同单各行同值），同时支持作为过滤参数与返回字段
- `customer_name` 仅作过滤条件，返回恒只给 `customer_code`（不返回客户名称与金额）；无 `as_of`，`shipped_qty` / `unshipped` / `status` 取当前值

### IF-7 `GET /api/v1/warehouses` — 工厂 / 仓库主数据
- 参数：`type?`（`plant|warehouse|port`）、`is_active?`(0/1)、`format?`
- 数据（**不分页**）：`[{ code, name, type, parent_code, parent_name, is_active, created_at, updated_at }]`

### `GET /api/v1/openapi.json` — OpenAPI 3.1 文档（公开）

2. **信封结构**：JSON 响应含 `code/message/data/_warnings`，分页接口含 `page.page/pageSize/total`
3. **IF-1 items**：`keyword` 过滤、`category_code` 过滤（无分类命中返回空）、分页 `total` 正确

7. **IF-3 历史时点**：`as_of` 早于入库 → 实物量（`on_hand`/`frozen`/`qc`/`total_qty`）为 0/或按重算；`reserved/in_transit/available/projected = null` 且 `_warnings` 非空

11. **IF-6 sales-orders**：行级字段（含 `order_no`/`line_no`/`order_date`/`warehouse_code`/`due_date`）齐全；`order_no`/`customer_code`/`customer_name`/`item_code`/`warehouse_code`/`order_date` 过滤、`status` 多值、`unshipped` 口径正确
12. **IF-7 warehouses**：`type` 过滤、`parent_code` 映射
13. **CSV**：`format=csv` → `Content-Type` 为 `text/csv`、响应体以 BOM 开头、首行列名与业务列序一致、空值列为空串、含逗号字段正确加引号；**不返回 JSON 信封**
