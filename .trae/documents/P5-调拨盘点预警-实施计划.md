### 已确定的范围决策

1. **调拨单为整单一次性发货 / 收货**：状态集为 `draft → confirmed → shipped → received`，**无 `partial`**。发货动作要求一次性发完所有行，收货亦然。表体的 `shipped_qty` / `received_qty` 仍如实累加（保持与 `transfer_transit` 在途口径一致），但动作语义为整单。这样既不改 schema，又天然满足库存查询在途口径。
2. **无新增迁移**：`0001` 已具备全部表，`biz_type` 已含所需类型。
3. **盘点过账以「实盘量」为准对齐账面**：创建草稿时快照 `book_qty` 供参考；**过账时逐行重读当前余额、重算 `diff_qty` 并回写**，保证过账后 `stock_balance` 精确等于 `counted_qty`（消除「创建 → 过账」之间的库存漂移）。
4. **预警支持两级规则**：`warehouse_id` 为空 = 全局规则（该物料**全部仓库** `on_hand` 汇总口径）；指定仓库 = 单仓规则（该仓 `on_hand`）。因 SQLite 对 `NULL` 的唯一性语义（`UNIQUE(item_id, warehouse_id)` 不约束 NULL），全局规则的唯一性**在服务层「先查后写」保证**。

## 核心算法与业务规则

### 1. 调拨单状态机（只能由业务动作推进）

```
draft 草稿 ──确认──→ confirmed 已确认 ──发货──→ shipped 在途(已发货) ──收货──→ received 已收货
   │                    │
   └──────取消──────────┴──→ cancelled 已取消
```

- 无「直接改状态」接口，只有 `confirm` / `ship` / `receive` / `cancel` 四个动作。
- `draft`：表头表体可改、可删、可确认、可取消。
- `confirmed`：表头表体**不可改**，可发货、可取消。
- `shipped`：**不可改、不可取消**（货已离源仓，只能继续收货）。
- `received` / `cancelled`：终态。

### 2. 发货（ship）：源仓 → 在途

一次请求在**一个事务**内完成：

1. 校验单据状态 = `confirmed`，否则 409
2. **按 `product_id` 合并整单请求量**（一单一行一物料，但同物料可能多行），逐组校验源仓物理可用量 `readBalanceByStatus(db, product, from_warehouse).available ≥ 合并量`，否则 409
   —— 引擎出库分支**不校验库存**（`postMovement` 只校验 `quantity > 0`），会写出负库存，**必须由 service 预检兜底**（与 P4 销售出库同一原则）
3. 逐行 `postMovement({ bizType: 'transfer_out', bizId: order.id, bizNo: order.order_no, direction: -1, stockStatus: 'available', productId, warehouseId: from_warehouse, quantity })`
   —— **不传 `unitCost`**：出库按源仓当前移动加权平均结转，源仓均价不变
4. 逐行 `UPDATE transfer_order_item SET shipped_qty = quantity`
5. 表头 `status = 'shipped'`、`updated_at`

发货后库存效果：源仓 `available` 减总量；`to_warehouse` 出现 `in_transit = 总量`（由 `transfer_transit` CTE 自动生效）；目标仓实物量暂不变。

### 3. 收货（receive）：在途 → 目标仓

一次请求在**一个事务**内完成：

1. 校验单据状态 = `shipped`，否则 409
2. 逐行取 `unitCost = readWarehouseCost(db, product, from_warehouse_id)`（**源仓**当前均价，作为调拨货品的结转成本）
3. 逐行 `postMovement({ bizType: 'transfer_in', bizId: order.id, bizNo: order.order_no, direction: +1, stockStatus: 'available', productId, warehouseId: to_warehouse, quantity, unitCost })`
   —— **必须显式传 `unitCost`**：入库按 `(目标仓现有量×目标仓现均价 + 调入量×源仓均价) / 总量` 重算目标仓均价；缺省会 fallback 0 把目标仓均价稀释为 0（与 P4 销售退货同一陷阱）
4. 逐行 `UPDATE transfer_order_item SET received_qty = quantity`
5. 表头 `status = 'received'`、`updated_at`

收货后库存效果：目标仓 `available` 增加、均价加权更新；`to_warehouse` 的 `in_transit` 归零。

### 4. 取消（cancel）

- `draft` / `confirmed` → `cancelled`（未发货，无任何库存流水）。
- `shipped` 及以后不可取消。

### 5. 盘点单状态机

```
draft 草稿 ──过账──→ posted 已过账
   │
   └──取消──→ cancelled 已取消
```

- `draft`：表头表体可改、可删、可过账、可取消。
- `posted`：终态（本阶段不做反审核 / 冲销）。
- `cancelled`：终态。

### 6. 盘点过账（post）：以实盘量对齐账面

一个事务内：

1. 校验状态 = `draft`，否则 409
2. 逐行（行维度 = `product_id × stock_status`，仓库取表头 `warehouse_id`）：
   - `bookNow = readBalanceByStatus(db, product, warehouse)[stock_status]`（**过账时点的真实账面量**）
   - `delta = counted_qty − bookNow`
   - `delta > 0`（盘盈）：`postMovement({ bizType: 'adjust', direction: +1, quantity: delta, stockStatus, unitCost: readWarehouseCost(...) })`
     —— **必须传入当前均价**，使 `avgCost = (qtyBefore×cost + delta×cost)/(qtyBefore+delta) ≡ cost`，**均价零漂移**
   - `delta < 0`（盘亏）：校验 `bookNow ≥ |delta|`（否则 409），`postMovement({ bizType: 'adjust', direction: -1, quantity: |delta|, stockStatus })`
     —— 出库分支自动携带当前成本，均价不变
   - `delta = 0`：不写流水
   - 回写 `book_qty = bookNow`、`diff_qty = delta`（记录真实调整依据，覆盖创建时的快照）
3. 表头 `status = 'posted'`、`posted_at = now`、`updated_at`

过账后 `stock_balance[product, warehouse, stock_status].quantity ≡ counted_qty`（对该行而言），流水 `biz_type = 'adjust'` 且 `direction` 随盘盈/盘亏。

### 7. 预警口径

- **规则**：`(item_id, warehouse_id?) → min_qty / max_qty`；`min_qty` 默认 0，`max_qty` 可空（不启用上限）；`is_active = 0` 不参与判断。
- **当前量**：
  - 仓库级规则：该 `(item, warehouse)` 的 `on_hand`（`stock_balance` 中 `stock_status = 'available'` 的数量）。
  - 全局规则（`warehouse_id` 为空）：该物料在**所有仓库**的 `on_hand` 之和。
- **告警判定**：
  - `current < min_qty` → `below_min`（低于下限）
  - `max_qty != null AND current > max_qty` → `above_max`（高于上限）
  - 同一条规则两条同时命中时，返回两行（或按 `below_min` 优先——实现取「分别返回」以便列表清晰，最终以单行 `alert_type` 呈现）。
- **预警清单**返回：`{ ruleId, itemId, productCode, productName, baseUnit, qtyPrecision, warehouseId?, warehouseName?, currentQty, minQty, maxQty, alertType }`。
