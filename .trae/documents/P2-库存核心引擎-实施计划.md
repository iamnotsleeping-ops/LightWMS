# P2 · 库存核心引擎 实施计划

## Context

P1 已交付基础资料、钉钉 SSO、用户/角色权限。业务侧目前只有主数据，还没有任何库存作业能力。

P2 要建立整个系统的**数据正确性地基**：`stock_transaction`（只增不改的账本）+ `stock_balance`（汇总快照）双表模型、移动加权平均成本、库存状态隔离、以及历史时点 `as_of` 从流水重算的能力。P3 采购、P4 销售、P5 调拨盘点、P7 对外 7 接口全部依赖本阶段产出的引擎函数与口径计算，因此**本阶段的算法必须一次写对**，后续阶段只做调用方。

`stock_transaction` / `stock_balance` / `stock_alert_rule` 三张表在 P0 的 `0001_init.sql` 已建好，P2 **不新增表、不新增迁移文件**。

已与用户确认的三项范围决策：
1. P2 = 后端引擎 + 接口 + 单测，**并包含**前端「库存查询 / 库存流水 / 库存状态管理」三页。
2. 库存口径（实物量三桶 `on_hand` / `frozen` / `qc` + `total_qty`，单据派生 `reserved` / `in_transit` / `available` / `projected`）**一次写全**，采购/销售表已存在，P3/P4 落地后数据自然填充。
3. 系统参数 `port_stock_as_inventory`（默认 false）**在 P2 生效**，并在响应 `_warnings` 回显该参数值。

## 核心算法（必须严格遵守的规格约束）

### 1. 移动加权平均成本 —— 按 `(物料, 仓库)` 维度，不区分 `stock_status`

`stock_balance` 按 `(product_id, warehouse_id, stock_status)` 分行，但 `avg_cost` 在该物料该仓库的**三行上必须保持一致**。

- **入库**（`direction = 1`，非 `status_change`）：
  - `Q0` = 该 (物料, 仓库) **全部状态**的 `quantity` 之和；`C0` = 当前 `avg_cost`
  - `Q0 + qty > 0` 时：`newAvg = Math.round((Q0 * C0 + qty * unitCost) / (Q0 + qty))`
  - `Q0 = 0` 时：`newAvg = unitCost`
  - 更新该 (物料, 仓库) **全部状态行**的 `avg_cost`
- **出库**（`direction = -1`）：用当前 `C0` 作为流水 `unit_cost` 结转，**不重算** `avg_cost`
- **库存为 0 时保留最后一次成本**，不清零
- **状态转移不重算成本**，只搬移 `quantity`

金额与成本均以「分」为整数存储，加权平均的除法用 `Math.round` 收敛。

### 2. 任何库存变动必须在同一事务内按序完成

规格要求的四步：① 写 `stock_transaction` ② 更新 `stock_balance`（含成本重算）③ 累加单据表体已执行数量 ④ 推进单据状态。

P2 的引擎只负责 ①②（③④ 由 P3/P4/P5 的单据服务在同一事务内接续）。引擎导出的写函数**各自内部包 `db.transaction()`**，`better-sqlite3` 对嵌套事务自动使用 SAVEPOINT，因此 P3/P4/P5 可以安全地把它们组合进更大的单据事务中。

### 3. 库存状态隔离

`available` / `frozen` / `qc` 三态。允许的转移：`available→frozen`（冻结）、`frozen→available`（解冻）、`qc→available`（质检放行）、`available→qc`（送检）。每次转移在同一事务内写**两笔** `status_change` 流水（出 + 入），校验来源状态数量充足，再搬移余额。

### 4. 库存口径（八列）

实物量三桶**独立成列**，不再有「frozen 含 qc」的合并口径（后期已按方案 A 拆分）：

```
on_hand    = Σ stock_balance.quantity WHERE stock_status = 'available'   -- 可用桶
frozen     = Σ stock_balance.quantity WHERE stock_status = 'frozen'      -- 冻结桶
qc         = Σ stock_balance.quantity WHERE stock_status = 'qc'          -- 待检桶
total_qty  = on_hand + frozen + qc                                       -- 账面物理量（三桶合计）
reserved   = Σ (sales_order_item.quantity − shipped_qty − cancelled_qty)
             WHERE sales_order.status IN ('confirmed','partial')
in_transit = 采购在途 + 调拨在途
             采购在途 = Σ (purchase_order_item.quantity − received_qty − cancelled_qty)
                        WHERE purchase_order.status IN ('confirmed','partial')
             调拨在途 = Σ (transfer_order_item.shipped_qty − received_qty)
                        WHERE transfer_order.status = 'shipped'  → 归属 to_warehouse_id
available  = on_hand − reserved                       -- 可承诺量 ATP
projected  = on_hand + in_transit − reserved          -- 预计可用
```

- 按 `(物料, 仓库)` 聚合，`qty_precision > 0` 的物料前端按精度展示。
- **不做事后裁剪**：`available` 允许为负（超卖是真实业务信号），禁止 `max(0, …)` 兜底。
- 排除已取消单据；`received` 的采购单与 `shipped`/`received` 的调拨单不再计入在途。

### 5. 港口仓口径

`port_stock_as_inventory = false`（默认）时，`warehouse.type = 'port'` 的仓库**不计入**实物量三桶（`on_hand` / `frozen` / `qc`，视为「在途到港」）；但其**在途仍参与计算**（规格 IF-7：`plant` 与 `warehouse` 参与库存与在途计算，`port` 默认只作为在途节点）。参数值在响应 `_warnings` 中回显。

### 6. as_of 历史时点

```
SELECT product_id, warehouse_id, stock_status, SUM(quantity * direction) AS qty
FROM stock_transaction WHERE occurred_at <= ? GROUP BY 1, 2, 3 HAVING qty <> 0
```

**禁止用当前余额近似。** 历史时点只能还原**实物量**（`on_hand` / `frozen` / `qc` / `total_qty`）；`reserved` / `in_transit` / `available` / `projected` 是单据派生量、依赖单据当时的状态，无法可靠还原，因此传 `asOf` 时这四项返回 `null`，并在 `_warnings` 中明确说明「历史时点不支持预留与在途口径」，不做近似兜底。

## 单元测试（规格第八节硬性要求）

测试用注入的 `:memory:` 数据库 + `runMigrations()` 建表，覆盖：

1. **流水与余额恒等**：`SUM(quantity * direction)` 按 物料+仓库+状态 分组 ≡ `stock_balance.quantity`
2. **移动加权平均**：0→100 件@5 分、再入 100 件@7 分 ⇒ `avg_cost = 6`；出库流水 `unit_cost` 取当前成本；库存归零后 `avg_cost` 保留
3. **状态隔离**（验收 10）：10 件 `available→qc` ⇒ 可用 −10、总量不变、`avg_cost` 不变；放行后恢复
4. **as_of 快照**（验收 9）：插入顺序为先出库后入库时，`as_of` 结果仍等于按 `occurred_at` 重算值
5. **在途**（验收 2/4）：采购 100 确认 → 入库 60 ⇒ 在途 40；再入 40 ⇒ 在途 0；调拨发货后调入仓在途 = 20
6. **事务完整性**（验收 5）：事务中途抛错后流水与余额均无变化
7. **projected**（验收 8）：`on_hand = 0` 但在途充足 ⇒ `projected > 0`
8. **港口仓口径**：`port` 仓余额不计入 `on_hand`，但计入在途
